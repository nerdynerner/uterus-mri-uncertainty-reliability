# Reproduction workflow

Run commands from the repository root. All computational outputs must use a new workspace. The original research files are unnecessary for workspace creation.

## Data and partitions

Download `UT-EndoMRI.zip` from https://zenodo.org/records/15750762. The provider MD5 is `7ace6e1b08efa10d0a1967073b0ba41c`. Extract the archive so that the workspace contains `data/original_v2/UT-EndoMRI/D1_MHS` and `data/original_v2/UT-EndoMRI/D2_TCPW`.

```sh
python scripts/prepare_workspace.py /absolute/path/to/new-workspace
export UTERUS_MRI_WORKSPACE=/absolute/path/to/new-workspace
export PYTHONPATH="$PWD/src"
```

The workspace path must be new. Place the extracted dataset in its `data/original_v2` directory. The fixed manifest records the included files and byte hashes. The accompanying screening summary records the established case selection, not a new contour review. Do not replace the fixed partitions with a fresh random split.

The source archive includes eight fewer D2 identifiers than the 81 described in the dataset paper; D2-030 through D2-037 were absent. This describes the downloaded archive, not independently established clinical identities.

Optional file and geometry audits use new output directories:

```sh
python src/audit_dataset.py "$UTERUS_MRI_WORKSPACE/data/original_v2" "$UTERUS_MRI_WORKSPACE/audit-files"
python src/audit_pair_geometry.py "$UTERUS_MRI_WORKSPACE/data/original_v2" "$UTERUS_MRI_WORKSPACE/audit-geometry"
```

These audits screen files and potential pairings. The fixed study manifest is the record of analytical eligibility. The original selection included representative overlay screening; fully recreating that judgement is not an automated step.

## Resource and integration checks

```sh
python src/benchmark_runtime.py "$UTERUS_MRI_WORKSPACE/outputs/benchmark_installed_256_2026-10-21.json" --size 256
python src/verify_integration.py "$UTERUS_MRI_WORKSPACE/outputs/integration_dtypefix_2026-10-21.json" --scratch "$UTERUS_MRI_WORKSPACE/tmp"
```

Training requires passing resource and integration records and rejects a synthetic process RSS above 3 GiB. This is a starting resource guard, not a full-study memory estimate. Training caches prepared volumes on disk; native ensemble and dropout arrays can require substantial storage. Runtime and storage requirements depend on the host and case geometry.

## Training, calibration and held-out inference

The following commands are computationally substantial and were not rerun during repository validation.

```sh
python src/run_prespecified_models.py --output-name models_v1
python src/evaluation_runner.py calibrate
python src/research_analysis.py fit
python src/evaluation_runner.py heldout
python src/research_analysis.py analyse
python src/verify_final_results.py
```

Training completes all six independent runs and selects checkpoints using validation cases. Calibration freezes uncertainty thresholds, then secondary probability temperatures, before held-out inference. Analysis uses the saved native arrays. Fresh training creates new checkpoint hashes and may produce different numerical results across hardware. The manuscript-associated selected checkpoints are described in `results/training_summary.json` and `results/evaluation_configuration.json`; they are not distributed.

`src/training_pipeline.py` retains the computational training implementation from the completed study. The training function in `src/pipeline.py` is equivalent; its inference function uses the evaluated packed-mask disagreement calculation.

New executions create code freeze records for the distributed files. Historical digest records in `results/` describe the completed study; they are not fresh-execution configuration files. Computational source versions and original digests are mapped in `config/source_lineage.json`.

## Analysis from recorded scores

```sh
python scripts/check_results.py
```

This recomputes frozen-threshold performance, risk-coverage and primary bootstrap calculations using the recorded calibration and held-out scores. It verifies exact partition membership, method counts, selected epochs and threshold reconstruction. Secondary image-based endpoints require native arrays and source references and are not regenerated by this command.

## Figures

```sh
python scripts/make_figures.py --output figure-reproduction
```

The figure script creates aggregate CSV tables from `results/final_analysis.json` and uses the study's base R plotting implementation to generate Figures 1-3 as PDFs. To plot a fresh complete analysis, pass `--results "$UTERUS_MRI_WORKSPACE/outputs/evaluation_v1_2026-10-21"`. Existing figure directories are preserved.
